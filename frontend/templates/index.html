Acerca de esta suite

CryptoLab es una plataforma educativa que implementa algoritmos criptográficos reales usando la librería cryptography (PyCA) de Python. Todas las operaciones ocurren en el servidor — no se almacenan claves ni mensajes entre sesiones.

Message Digest

Genera resúmenes digitales (hashes) de longitud fija para cualquier mensaje.

¿Qué hace este algoritmo?

Una función hash criptográfica toma cualquier mensaje de longitud arbitraria y produce una cadena de bits de longitud fija (el digest). El resultado es determinista, rápido de calcular e imposible de revertir.

¿Cómo funciona?
  • SHA-256: Produce 256 bits. Estándar NIST, usado en TLS, certificados y firmas digitales.
  • SHA-3-256: Variante Keccak aprobada por NIST en 2015. Arquitectura diferente a SHA-2.
  • MD5: Produce 128 bits. Obsoleto para seguridad, pero útil para checksums no críticos.

Firma Digital RSA

Garantiza autenticidad e integridad usando RSA-PSS con SHA-256.

¿Qué hace este algoritmo?

La firma digital RSA-PSS permite al emisor demostrar que un mensaje fue enviado por él (autenticidad) y que no fue alterado en tránsito (integridad). Solo el poseedor de la clave privada puede firmar; cualquiera con la clave pública puede verificar.

¿Cómo funciona?
  • Generación: Se genera un par de claves RSA-2048 (pública + privada).
  • Firma: La clave privada firma el hash SHA-256 del mensaje usando RSA-PSS.
  • Verificación: La clave pública verifica que la firma corresponde al mensaje.
  • PSS vs PKCS1v15: PSS es el esquema moderno recomendado por NIST (SP 800-131A).

Cifrado Simétrico AES-256-GCM

Cifrado autenticado: confidencialidad e integridad en una sola operación.

¿Qué hace este algoritmo?

AES-256-GCM cifra un mensaje con una clave compartida (simétrica) de 256 bits. El modo GCM (Galois/Counter Mode) proporciona tanto cifrado como autenticación: si alguien altera el texto cifrado, la verificación del tag fallará.

¿Cómo funciona?
  • Clave: 32 bytes aleatorios (256 bits). Debe mantenerse secreta.
  • IV / Nonce: 12 bytes aleatorios únicos por cada cifrado. Nunca reutilizar con la misma clave.
  • Tag GCM: 16 bytes que verifican la integridad. Si se altera el mensaje, el tag no coincide.

Cifrado Asimétrico RSA-OAEP

Cifra con la clave pública del destinatario; solo él puede descifrar con su clave privada.

¿Qué hace este algoritmo?

RSA-OAEP permite que cualquier persona con la clave pública cifre un mensaje, pero solo el propietario de la clave privada correspondiente puede descifrarlo. Esto resuelve el problema del intercambio de claves en comunicación segura.

¿Cómo funciona?
  • OAEP: Optimal Asymmetric Encryption Padding. Añade aleatoriedad al cifrado, resistiendo ataques de padding oracle.
  • Limitación: RSA-OAEP con SHA-256 y clave de 2048 bits solo puede cifrar ~190 bytes directamente.
  • En producción: Se usa un esquema híbrido RSA+AES: AES cifra el mensaje, RSA cifra la clave AES.

ECC — Curvas Elípticas (ECDSA)

Firma y verifica con ECDSA en curva P-256: máxima seguridad, claves compactas.

¿Qué hace este algoritmo?

ECDSA (Elliptic Curve Digital Signature Algorithm) realiza firmas digitales usando la matemática de curvas elípticas. Ofrece la misma seguridad que RSA con claves significativamente más pequeñas, lo que lo hace ideal para dispositivos con recursos limitados.

¿Cómo funciona?
  • Curva P-256 (SECP256R1): Curva estándar NIST. Usada en TLS 1.3, JWT y passkeys.
  • Tamaño de clave: 256 bits vs 2048 bits de RSA para seguridad equivalente.
  • Velocidad: Operaciones hasta 10× más rápidas que RSA equivalente.
